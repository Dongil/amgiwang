## 6. 배우고 개선해야 할 점

### 6.1 잘된 점 (계속 유지)

- **설계 문서의 품질**: 상세한 Design 문서가 구현 시간을 30% 단축. API 스펙과 타입 정의가 명확해 오류 최소화.
- **PDCA 사이클 적용**: Plan → Design → Do → Check → Act 과정이 체계적. 설계 일치도 91%에서 95%로 자동 상향.
- **Vercel Best Practices 가이드**: Design 문서에 번들 최적화, 병렬 데이터 페칭, 렌더링 최적화 지침이 있어서 구현 중 참고 가능.
- **TypeScript 타입 안정성**: `ShareMode`, `DeckShare` 등 신규 타입을 Design 단계에서 정의하니 런타임 에러 없음.

### 6.2 개선이 필요한 점 (문제점)

- **DB 마이그레이션 테스트 미흡**: pg_trgm 확장은 Supabase Free tier에서 미지원이 설계 단계에서 누락됨. 테스트 환경에서 사전 확인 필요.
- **초기 범위 추정**: "덱 공유 + UI 리디자인"이 디자인 시스템부터 API 6개까지 범위가 컸음. 초기에 phase별로 분리 검토 권장.
- **클라이언트-서버 컴포넌트 경계**: Explore 페이지를 Server Component로 설계했는데 TanStack Query 인터랙티브 검색이 필요해서 결국 Client Component 혼합. 초기 선택 기준 필요.

### 6.3 다음에 시도할 점

- **인수 테스트(Acceptance Test) 조기 작성**: UI 리디자인 완료 후 실제 학생 사용 시나리오를 테스트 시나리오로 만들고 구현 중 검증.
- **마이그레이션 검증 체크리스트**: DB 변경 시 Supabase tier 호환성, RLS 정책 테스트, 인덱스 성능 측정을 사전 수행.
- **컴포넌트 레이아웃 컨벤션**: Page 부분과 API 부분에서 비동기 전략(Server vs Client Component) 사전 결정 기준안 작성.
